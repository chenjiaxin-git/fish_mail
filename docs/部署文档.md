# 生鲜水产系统部署文档

本文供负责单机Linux部署的运维人员使用，覆盖首次安装、升级、MinIO图片迁移、订阅消息配置以及备份恢复。交付以Docker Compose为入口；真实微信发送、商户收款和公网回调需在实际环境另行联调。

## 1 环境与交付内容

建议使用Linux x86_64服务器，预留至少4核、8GB内存和足够数据磁盘。构建Go版MinIO及Java、前端镜像时会额外消耗CPU、内存和磁盘。需要Docker Engine、Docker Compose V2、Python3、POSIX shell、GNU tar/find、sha256sum；从源码构建需要访问GitHub、Go模块代理、Maven Central、npm及基础镜像仓库。

服务包括MySQL8、MinIO、一次性MinIO初始化、Java17后端和Nginx管理端。MySQL、MinIO API/控制台和后端不发布公网端口，只有Nginx发布80/443。后端同时加入出站网络以访问微信，数据库与对象存储位于内部网络。

MinIO官方预构建镜像在本次环境拒绝访问，交付改用官方固定版本源码构建：

| 组件 | 版本或来源 | 用途 |
| --- | --- | --- |
| MinIO | RELEASE.2025-09-07T16-13-09Z | 私有商品图片桶 |
| mc | RELEASE.2025-08-13T08-35-41Z | 建桶、创建专用账号及授权 |
| MinIO Java SDK | 8.5.17 | S3上传、读取与迁移 |
| MySQL | Compose默认8.0.44，可改为已审核镜像摘要 | 业务数据 |
| 后端/管理端 | delivery-v1构建标签；正式发布应使用独立版本及摘要 | 应用与静态文件 |

对应源码：[MinIO固定版本](https://github.com/minio/minio/tree/RELEASE.2025-09-07T16-13-09Z)、[mc固定版本](https://github.com/minio/mc/tree/RELEASE.2025-08-13T08-35-41Z)。服务端及mc采用AGPLv3，镜像保留许可证；分发交付镜像时同时提供对应源码及许可证。Java SDK采用Apache-2.0。请保存每次构建的镜像摘要和源码版本。

## 2 准备配置

在仓库根目录执行：

```sh
cp deploy/.env.example deploy/.env
mkdir -p deploy/certs deploy/secrets
chmod 700 deploy/certs deploy/secrets
chmod 600 deploy/.env
```

编辑.env填入实际值，勿把该文件提交仓库。密码和JWT密钥可使用密码生成器或openssl rand -hex 32分别生成，管理员与用户JWT不得共用。生产环境变量需要显式注入；backend中的示例env文件不会被Spring自动读取。

| 变量 | 配置要求 |
| --- | --- |
| MYSQL_PASSWORD / MYSQL_ROOT_PASSWORD | 独立强密码，业务使用fishmall账号 |
| JWT_SECRET / JWT_USER_SECRET | 两个独立随机密钥，每个至少32字节 |
| ADMIN_INITIAL_PASSWORD | 首次管理员密码，初始化后由后台修改；改此变量不会重置已有密码 |
| WECHAT_APPID / WECHAT_SECRET | 真实小程序配置，生产禁止Fake或touristappid回退 |
| MINIO_ROOT_USER / MINIO_ROOT_PASSWORD | 仅用于MinIO管理与初始化 |
| MINIO_ACCESS_KEY / MINIO_SECRET_KEY | 专用应用账号，必须与root账号不同 |
| NOTIFICATION_ENABLED | 默认false，真实模板与授权验证后再开启 |
| NOTIFICATION_MINIPROGRAM_STATE | formal正式版、trial体验版、developer开发版 |
| WECHAT_PAY_ENABLED | 默认false，沿用backend/payment.env.example的真实支付配置 |
| ORDER_TIMEOUT_CLOSE_ENABLED | 默认true，启动后会处理已有到期订单 |
| COMPOSE_PROJECT_NAME | 生产固定项目名，恢复演练必须另用项目名 |
| CERT_DIR / CONFIG_DIR / PAYMENT_KEY_DIR | 可覆盖证书、附加配置和支付密钥只读挂载目录 |

生产profile拒绝空密钥、常见示例JWT、共享JWT、缺失微信登录配置及意外本地存储。该检查不能证明真实微信凭据有效，仍需实际验证登录。

将完整证书链保存为deploy/certs/fullchain.pem，私钥保存为privkey.pem。Nginx只启用TLS1.2/1.3。证书由目标环境提供，本项目不自动申请证书或修改DNS。支付私钥、公钥分别放入secrets/merchant-private.pem、secrets/wechat-public.pem，再按既有支付设计配置商户号、公钥ID和APIv3 Key。Linux上只读挂载不会授予读取权限：支付密钥目录及文件需允许容器UID10001访问，建议由维护人员将该目录属主设为10001:10001、目录权限700、密钥文件600；Nginx证书由其root进程读取。不要通过放宽到全员可读解决密钥权限问题。

## 3 构建与首次启动

```sh
sh deploy/scripts/preflight.sh
docker compose --env-file deploy/.env -f deploy/compose.yml build
docker compose --env-file deploy/.env -f deploy/compose.yml up -d --wait
```

preflight检查配置语法和证书文件存在；容器启动时继续验证密钥和业务配置。MySQL健康后后端通过Flyway追加应用V1至V10；不得修改已经发布的旧迁移。首次MinIO初始化建立私有fishmall-images桶和专用应用账号，只允许products/前缀下的读取/写入及必要列举，不允许应用删除对象，也不开放匿名桶访问。

后台静态站点由Nginx提供，/api反代到后端，/uploads/products反代受控图片入口，Vue历史路由刷新可用。/actuator不公开，容器内部/actuator/health同时检查数据库和MinIO就绪状态。默认上传单文件最大5MB，Nginx请求体上限6MB。

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml ps
docker compose --env-file deploy/.env -f deploy/compose.yml exec -T backend curl -fsS http://localhost:8080/actuator/health
```

后端首次启动创建管理员admin。登录后修改密码，创建分类和商品，上传图片并确认页面可以读取。正常停止时使用docker compose stop；生产不要执行down -v，后者会删除数据卷。

## 4 MinIO与已有图片迁移

新图片上传到MinIO，地址继续使用/uploads/products/文件名。读取先查MinIO，仅NoSuchKey时回退旧本地图片；桶缺失、权限或连接异常返回失败，不能伪装成图片不存在。

已有图片应复制到本项目legacy_images卷，保留原UUID文件名。目录内只放jpg/jpeg/png/webp图片，文件需要后端UID10001可读。可使用临时辅助容器将旧目录复制到卷内；迁移前备份并确认Compose项目名，不能覆盖其他项目的同名卷。

暂停业务写入后执行：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml stop nginx backend
sh deploy/scripts/migrate-images.sh
docker compose --env-file deploy/.env -f deploy/compose.yml start backend nginx
```

迁移只复制，逐文件计算SHA-256；目标相同内容跳过，内容冲突或路径异常停止并报告，不自动覆盖、不删除原图。迁移后核对商品、轮播和历史订单图片，旧卷保留到备份恢复验证完成。MinIO API与控制台保持内部可达，运维访问按目标环境受控通道处理，不新增公网映射。

## 5 订阅消息配置与验证

在小程序平台开通并取得三类实际模板：订单提交、商家报价、订单配送完成。复制config/notifications.example.yml为notifications.yml，按真实模板ID及字段定义逐项替换，示例编号不能直接作为真实配置。

字段映射支持orderNo、summary、amount、time、note；微信字段键使用实际thing、character_string、amount、time、date、phrase或number编号。普通说明按微信类型长度截断，订单号等标识超长则记录失败。金额从整数分格式化。模板按事件保存快照，修改配置后需发布/重启应用，已登记任务不更换内容。

先在真实体验版配置NOTIFICATION_MINIPROGRAM_STATE=trial，核实AppID一致、模板字段、请求域名和平台IP白名单等实际要求，再按授权范围启用NOTIFICATION_ENABLED。正式发布后切回formal。缺失或示例模板会阻止启用；默认关闭不会伪造发送成功，也不会补发关闭期间登记的任务。

小程序在下单按钮点击时申请最多三类一次性订阅，用户接受、部分拒绝、调用失败或不支持都不影响下单。重新报价受真实授权额度限制；商家提醒继续使用后台轮询。

| 任务状态 | 含义与处理 |
| --- | --- |
| PENDING | 待发送或明确可恢复错误后等待退避 |
| SENDING | 已领取，外部调用进行中 |
| SUCCESS | 微信接口明确接受，不代表用户已读 |
| FAILED | 拒收、授权不足、配置错误或有限重试耗尽 |
| SKIPPED | 发送关闭、模板未配置、事件过期或报价已不适用 |
| UNKNOWN | 网络结果不确定或发送进程中断，不自动重发 |

后台单独线程默认每轮结束后30秒处理，默认每批20条、最多3次尝试；网络请求默认5秒。结果UNKNOWN不得直接改表重发；核查任务及当前订单，避免重复通知或消耗下一次授权。发送失败不修改已提交订单、库存或付款状态。

可用以下只读查询排障，勿输出完整openid、Token、手机号或密钥：

```sql
SELECT id, order_id, template_type, state, attempt_count, error_message
FROM message_log ORDER BY id DESC LIMIT 50;
```

## 6 小程序与微信支付上线前准备

将miniprogram/project.config.json的touristappid替换为真实AppID，miniprogram/config.js的apiBaseUrl改为https://实际域名/api/v1。使用真实HTTPS证书，配置微信平台request、uploadFile、downloadFile合法域名，真机验证登录和图片加载。不要依赖开发者工具的“忽略合法域名校验”作为发布验证。

微信支付开关独立于订阅消息。真实联调需按wechat_payment_sign设计准备商户绑定、公钥模式、HTTPS通知地址和密钥；验证可信回调、查单、关单、重复通知与库存，再执行授权测试订单。当前交付未执行真实收款、通知或公网上线。

## 7 备份与保留

备份脚本要求backend/nginx正在运行，会停止这两个服务以暂停写入，备份完成或失败后尝试恢复原服务。维护窗口内不要通过其他客户端修改MySQL或MinIO。

```sh
sh deploy/scripts/backup.sh
# 可选：将备份放到专门磁盘
BACKUP_DIR=/srv/fishmall-backups sh deploy/scripts/backup.sh
```

每份快照包含数据库SQL、MinIO图片与images.sha256、旧本地图片、部署.env/Compose/Nginx、附加配置、支付密钥及TLS证书归档和snapshot.sha256。COMPLETE标记只在全部完成后写入。目录权限受限，但压缩不是加密；将快照加密后存到独立介质，并限制密钥与恢复权限，不能当作公开代码交付包分享。

默认保留至少7天，仅清理指定备份目录中符合fishmall时间戳格式且带COMPLETE的旧快照。脚本不自动安装宿主机计划任务。运维可审核后配置每日调度，例如：

```cron
0 3 * * * /bin/sh /opt/fishmall/deploy/scripts/backup.sh >> /var/log/fishmall-backup.log 2>&1
```

以命令进程退出码及COMPLETE标记判断备份成功，不能只依据日志中出现“完成”。恢复旧图片使用独立辅助容器写入新空卷，不向后端的只读挂载写入。

## 8 恢复演练与灾难恢复

恢复脚本只允许空数据库，并要求backend/nginx已停止，不提供覆盖已有生产库的快捷开关。恢复到另一套Compose项目和新的数据卷，先保留原环境及恢复前备份。

1. 选择完整快照，解密到受限目录并核对snapshot.sha256。
2. 审核快照中的部署配置，复制为新项目.env，修改COMPOSE_PROJECT_NAME和监听端口。按目标环境重新提供证书、附加配置及密钥，不自动把旧配置覆盖到线上。
3. 启动新项目mysql、minio、minio-init，保持backend/nginx未启动。
4. 指定新项目的ENV_FILE并执行恢复。

```sh
ENV_FILE=/opt/fishmall/deploy/restore.env sh deploy/scripts/restore.sh /srv/backup/fishmall-时间戳 --confirm-empty-target
```

脚本核对清单，导入空库，按SHA-256导入MinIO对象，并恢复受校验的旧图片归档。恢复失败可能留下部分数据；保留失败现场，在另一个全新项目重新演练，不能跳过空库检查继续覆盖。

5. 启动新项目backend/nginx，核对历史订单、报价版本、最终金额、实称数量、库存流水和新旧图片，再决定业务切换。
6. 证书、密钥和.env独立审核恢复；脚本不自动启用支付或消息。完成切换前保留原项目与快照。

## 9 升级与回退

升级前运行预检和备份，保存当前应用镜像ID/摘要及配置版本，再构建或拉取已经测试的新版本。生产镜像使用唯一版本标签，保留旧镜像，不在升级过程中清理数据卷。

维护窗口停止nginx/backend写入，启动新后端并等待健康，再启动或重建nginx；后端容器重建后应重载nginx以重新解析内部地址。普通运行中的重载命令为：

```sh
docker compose --env-file deploy/.env -f deploy/compose.yml exec -T nginx nginx -s reload
```

应用回退通过切回旧镜像版本执行，Flyway迁移不会自动撤销。V10是追加通知字段/索引，历史日志保留；回退前核实旧镜像与已迁移数据库兼容。需要数据恢复时按第8节恢复到新项目后再切换，不能用回退镜像代替恢复数据库。

## 10 常见故障

| 现象 | 核查与处理 |
| --- | --- |
| 镜像源403/401或下载410 | 本交付可从固定官方GitHub源码构建MinIO/mc；先预拉取基础镜像，核对网络及自有镜像仓库，保留摘要 |
| 生产启动失败 | 检查独立JWT、真实微信登录配置、MinIO类型及模板字段，不开启Fake回退 |
| health为DOWN | 检查MySQL、MinIO健康与卷权限，再查看应用日志；不在公网开放actuator |
| MinIO初始化失败 | 核对root凭据、私有桶、专用账号及policy；应用账号不能与root同名 |
| 图片503 | 检查对象存储网络/权限/桶，不把连接异常当作本地回退条件 |
| 旧图片404 | 检查UUID文件名、本地卷挂载及权限，先复制迁移，不删除原图 |
| 报价消息未收到 | 核对微信授权额度、模板字段、报价版本和截止时间，查看message_log |
| 备份缺COMPLETE | 不用于恢复；核查退出码、存储空间和图片清单，旧业务服务恢复情况 |
| 迁移内容冲突 | 保留两端原文件，核对SHA-256和引用订单，人工确认后处理，不自动覆盖 |

本次实际演练、测试数量、未完成的真实环境项目见design/subscription_deployment_delivery_sign.md。敏感日志、密钥和快照不进入仓库。
