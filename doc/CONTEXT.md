## 文档定位

本文件是执行开发任务时的项目上下文和不可变边界。详细设计和完整字段说明见 docs/开发设计文档.md；本文只提供 AI 需要优先加载的基础信息、技术栈、全局约束和当前项目状态。

## 项目基础信息

- 项目名称：生鲜水产线上经营系统。
- 产品来源：《卖鱼商家小程序产品功能报告.docx》。
- 产品形态：客户微信原生小程序 + 商家 PC 管理后台 + Java API 服务。
- 业务模式：用户浏览商品并提交预订单，商家接单后按实际称重调整数量和金额，用户确认最终金额并支付，商家安排人员自配送。
- 交付范围：一期核心经营闭环；不含营销、会员、多门店、多角色、短信、骑手和配送轨迹。
- 设计文档版本：v1.0.0，当前对应的产品决策为“预下单后改价”。
- 金额和库存是首要正确性目标；UI 允许简约商用风格。

## 全局约束

1. 金额字段统一使用整数分和 BIGINT，禁止浮点数；重量和称重数量使用 DECIMAL(12,3)。
2. 订单状态只能通过统一状态机变更，不能在 Controller、Mapper 或定时任务中直接改状态。
3. 价格固定于用户支付前确认；已支付订单禁止改价、补差和自动退款。
4. 订单创建预占库存，支付成功才正式扣减；取消、关闭或超时释放预占库存。
5. 所有库存变更写 stock_ledger，支付和库存变更必须幂等并可按订单号追踪。
6. 微信支付回调必须验签、校验商户号和金额、处理重复通知；客户端支付结果不能作为成功依据。
7. 所有管理接口必须鉴权；用户只能访问本人地址、购物车和订单。
8. 分页 pageSize 最大 100，导出范围最大 31 天；所有输入做服务端校验。
9. 敏感配置通过环境变量注入，真实密钥、微信私钥、数据库密码不能提交仓库或打印日志。
10. 不实现会员、优惠券、营销、多门店、多角色、短信、骑手、地图轨迹、财务对账等二期能力。
11. 外部通知失败不回滚订单，但必须写 message_log；后台订单提醒依赖后台看板和轮询。
12. 实现完成后必须覆盖状态机、金额、库存并发、支付幂等、权限和导出测试。

## 订单状态摘要

CREATED 待商家确认 -> QUOTED 待用户确认价格 -> PENDING_PAYMENT 待支付 -> PAID_WAIT_DELIVERY 待配送 -> DELIVERING 配送中 -> COMPLETED 已完成。

旁路状态：CANCELLED（用户或商家取消）、CLOSED（确认或支付超时自动关闭）。  
支付后取消仅允许商家人工在微信商户平台原路退款，并在后台登记 refund_reference。

## 业务默认值

- 订单确认超时：1440 分钟。
- 商家报价后的支付超时：60 分钟。
- 规格计价方式：PIECE（整数件）或 WEIGHT（kg，三位小数，默认步进 0.5）。
- 地址上限：每个用户 20 个。
- 上传图片：jpg、png、webp，最大 5 MB。
- 管理员：一期仅单管理员账号。
- 时区：Asia/Shanghai；金额币种：CNY。

## 开发完成定义

- 后端编译和测试通过，Flyway 可从空库创建完整结构。
- 管理端可完成登录、商品、库存、改价、订单状态和导出操作。
- 小程序可完成登录、地址、购物车、下单、改价确认、支付和订单查询。
- 支付重复回调、并发抢库存、超时关闭、越权访问均有自动化或明确手测记录。
- 密钥未入库，部署文档和商家手册可由非开发人员执行。
